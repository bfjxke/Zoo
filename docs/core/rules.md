# GuardianEye-IIoT 沙箱动物园 - 游戏规则白皮书

> 本文档是游戏的"规则宪法"，所有游戏逻辑必须严格遵循此文档。
>
> **版本历史**：
> - v1.0: 初始版本
> - v1.1: 生命值调整，饥饿惩罚重做，和平结局机制
> - v1.2: Phase 4资源博弈与AI判官系统

## 一、时间系统

### 1.1 回合（Tick）

| 参数 | 数值 |
|------|------|
| Tick间隔 | 30秒 |
| 最大回合数 | **60回合**（v1.2从50改为60） |
| 秩序之剑生成 | 第40回合 |

### 1.2 Tick结算流程

```
阶段1：被动消耗
  → 所有存活的Agent每回合扣除耐力和饱食度
  → 禁闭Agent每回合禁闭时长-1

阶段1.5：秩序之剑生成检查
  → 第40回合时在随机位置生成秩序之剑

阶段2：死亡处理
  → 检查死亡的Agent是否到时复活
  → 死亡时食物掉落在原地
  → 持有秩序之剑的Agent死亡时剑掉落

阶段2.5：空投物资检查
  → 每11轮在D、E节点各投放30份食物

阶段3：AI决策
  → 调用Python调度器，让AI Agent做出决策

阶段4：状态保存
  → 保存游戏状态到数据库
```

## 二、Agent属性系统

### 2.1 五项基础属性

| 属性 | 含义 | 初始值 | 上限 |
|------|------|--------|------|
| 耐力(Stamina) | Agent的体力，决定能执行多少动作 | 100 | 100 |
| 饱食度(Satiety) | Agent的饱饿程度，耗尽会扣健康 | 100 | 140（含Buff） |
| 健康(Health) | Agent的生命值，归零则死亡 | 90 | 90 |
| **携带食物(CarriedFood)** | Agent随身携带的食物数量 | 0 | 20 |
| **禁闭轮数(ConfinementTicks)** | 禁闭剩余回合数 | 0 | - |

### 2.2 状态判定规则

| 状态 | 触发条件 | 效果 |
|------|----------|------|
| 疲劳(Fatigued) | 耐力 < 20 | 耐力消耗×1.5，恢复效果降低 |
| 饥饿(Hungry) | 饱食度 < 30 | 耐力消耗×1.5，每回合扣20健康 |
| 饱食回血 | 饱食度 > 30 | 每回合回复5健康 |
| 饱餐Buff | 饱食度 > 100 | 耐力恢复×1.7，每回合回复10健康 |
| **禁闭(Confined)** | confinementTicks > 0 | 不能执行任何动作，属性固定 |
| 死亡(Dead) | 健康 ≤ 0 | 无法行动，等待复活 |

### 2.3 禁闭系统

**触发条件**：
- 偷窃被抓（关3轮）
- AI判官拒绝（关1-5轮）

**禁闭效果**：
- 不能执行任何动作
- 属性保持不变（不消耗耐力/饱食度）
- 每轮禁闭时长-1
- 禁闭结束恢复正常

**特殊**：秩序之剑持有者被禁闭时，剑不掉落（除非是被抓偷窃）

### 2.4 属性惩罚叠加规则

**重要**：疲劳和饥饿的惩罚可以叠加！

| 状态组合 | 耐力消耗倍率 | 饱食消耗倍率 |
|----------|--------------|--------------|
| 正常 | ×1.0 | ×1.0 |
| 只有疲劳 | ×1.5 | ×1.0 |
| 只有饥饿 | ×1.5 | ×1.0 |
| 疲劳+饥饿 | ×2.25 | ×1.0 |

## 三、动作系统

### 3.1 白名单动作（无需AI判官审批）

以下是9个"预设合法"的动作：

#### 3.1.1 移动(Move)

- **消耗**：15点耐力（受状态惩罚影响）
- **限制**：
  - 目标节点必须在当前节点的相邻列表中
  - 耐力必须足够支付消耗

#### 3.1.2 进食(Eat)

- **恢复**：+40点饱食度（v1.2从30改为40）
- **上限**：饱食度最高可到140（超量进食）
- **限制**：饱食度已达140时无法再吃
- **特殊效果**：当饱食度 > 100时，获得"饱餐Buff"
- **进食优先级**：
  1. 先吃携带的食物（carriedFood > 0）
  2. 再从营地库存吃（从自己阵营库存扣1份）
  3. 营地库存为空则进食失败

#### 3.1.3 休息(Rest)

- **恢复**：+20点耐力（受状态惩罚和Buff影响）
- **限制**：耐力已达100时无法再休息
- **计算公式**：
  ```
  实际恢复 = 20 / 状态惩罚 / Buff加成
  例如：疲劳状态 + 有Buff = 20 / 1.5 / 0.588 ≈ 23点
  ```

#### 3.1.4 发言(Talk)

- **消耗**：无
- **频道**：`public`、`lawful_private`、`aggressive_private`、`neutral_private`
- **限制**：阵营私聊必须站在阵营基地

#### 3.1.5 交易(Trade)

- **消耗**：30点耐力（受状态惩罚影响）
- **限制**：耐力必须足够

#### 3.1.6 挑衅(Provoke)

- **消耗**：无
- **效果**：无实际数值影响，但可能影响AI心理

#### 3.1.7 领取食物(Claim_Food) v1.2新增

- **条件**：在阵营基地
- **限制**：携带量<20，营地库存>0
- **效果**：从营地库存取1份，Agent携带量+1

#### 3.1.8 捡起食物(Pickup_Food) v1.2新增

- **条件**：当前位置有食物掉落
- **限制**：携带量<20
- **效果**：从场景取1份，Agent携带量+1

#### 3.1.9 偷窃(Steal) v1.2新增

- **条件**：在对方阵营基地
- **成功条件**：基地内无另外两个阵营的人
- **偷窃上限**：每次最多3份
- **成功率**：满足条件时100%成功
- **被抓条件**：基地内有其他阵营的人
- **被抓后果**：关禁闭3轮，偷窃失败

## 四、资源系统 v1.2新增

### 4.1 空投物资

| 参数 | 数值 |
|------|------|
| 投放周期 | 每11轮 |
| 投放地点 | D节点（守序广场）、E节点（激进广场） |
| 每次投放量 | 各30份 |
| 可采集者 | 到达该节点的任何Agent |

### 4.2 营地食物库存

| 参数 | 数值 |
|------|------|
| 初始值 | 每阵营基地20份 |
| 消耗方式 | Agent吃食物时从库存扣1份 |
| 不可共享 | 各阵营库存独立 |
| 不可转移 | 不能跨阵营转移食物 |

### 4.3 食物携带

| 参数 | 数值 |
|------|------|
| 携带上限 | 20份 |
| 获取方式 | 在营地领取 / 在场景捡起 |
| 效果 | 与在营地吃效果相同 |
| 死亡掉落 | 死亡时食物掉落在原地，任何人可捡 |

### 4.4 食物消耗流程

```
Agent执行eat动作：
    ↓
┌─────────────────────────────────────┐
│ 饱食度 >= 140?                      │
│   是 → 进食失败                      │
│   否 → 继续                          │
└─────────────────────────────────────┘
    ↓
┌─────────────────────────────────────┐
│ carriedFood > 0?                    │
│   是 → carriedFood-1，饱食+40        │
│   否 → 继续                          │
└─────────────────────────────────────┘
    ↓
┌─────────────────────────────────────┐
│ 营地库存 > 0?                        │
│   是 → 库存-1，饱食+40               │
│   否 → 进食失败                      │
└─────────────────────────────────────┘
```

### 5.1 被动消耗（每回合自动发生）

|------|----------|----------|----------|

### 5.2 休息恢复

| 状态 | 恢复公式 | 实际恢复 |
|------|----------|----------|
| 正常 | 20 | 20 |
| 疲劳 | 20 / 1.5 | 13 |
| 有Buff | 20 / 0.588 | 34 |

| 条件 | 效果 |
|------|------|
| 饱食度 > 100 | 每回合回复10健康（饱餐Buff） |
| 饱食度 > 30 | 每回合回复5健康 |
| 饱食度 ≤ 30 | 每回合扣除20健康（饥饿惩罚） |

## 九、游戏结束条件

### 9.1 斗争结局

**触发条件**：只剩下一个阵营的Agent存活

**效果**：该阵营获胜，游戏结束

### 9.2 死亡结局

**触发条件**：所有Agent死亡且无法复活

**效果**：无人获胜，游戏结束

### 9.3 永无止境结局 v1.2更新

**触发条件**：达到最大回合数（**60回合**，从50改为60）

**效果**：游戏结束，无人获胜（平局）

### 9.4 和平结局

**触发条件**（需同时满足）：
1. 游戏进行至少40回合
2. 所有阵营都有Agent存活
3. 守序阵营持有"秩序之剑"
4. 守序阵营在公共频道发布"秩序宣言"
5. 激进阵营超过半数同意

## 十、秩序之剑系统

### 10.1 生成规则

- **生成时间**：第40回合
- **生成位置**：随机节点（D、E、F、G、H之一）
- **唯一性**：整局游戏只有一把

### 10.2 持有效果

| 阵营 | 持有效果 |
|------|----------|
| 守序阵营 | 全员10%属性加成 + 可发布秩序宣言 |
| 其他阵营 | 无特殊效果（但可阻止守序阵营获得） |

### 10.3 抢夺与掉落机制 v1.2更新

- Agent移动到秩序之剑所在节点即可拾取
- 拾取后，剑跟随Agent移动
- **死亡或被抓偷窃时，剑掉落在当前位置**
- 任何人可捡起

### 10.4 秩序宣言

- **发布者**：守序阵营持有秩序之剑的Agent
- **发布地点**：公共频道
- **冷却时间**：10回合
- **效果**：触发和平结局投票

## 十一、AI判官系统 v1.2新增

### 11.1 触发条件

当Agent执行自定义动作（不在白名单的动作）时

### 11.2 判断依据

- 当前游戏状态（Agent属性、位置、周围环境）
- 最近游戏日志（观察者模式记录）
- 约60%通过率

### 11.3 缓存机制

- 相同行为8轮内不重复判断
- 直接返回上次结果

### 11.4 输出格式

```json
{
  "approved": true/false,
  "confinement_ticks": 0-5,
  "reasoning": "判断理由"
}
```

### 11.5 违规惩罚

- 批准：执行动作
- 拒绝：根据情况关禁闭1-5轮

## 十五、偷窃机制详解 v1.2新增

### 15.1 偷窃流程

```
Agent进入对方营地
    ↓
┌─────────────────────────────────────┐
│ 基地内有其他阵营的人？              │
│   是 → 被抓，关禁闭3轮              │
│   否 → 继续                          │
└─────────────────────────────────────┘
    ↓
┌─────────────────────────────────────┐
│ 对方营地库存 > 0?                    │
│   是 → 偷取1-3份                     │
│   否 → 偷窃失败                      │
└─────────────────────────────────────┘
```

### 15.2 被抓判定

- 基地内有**其他两个阵营**的任意一个人 → 被抓
- 只考虑"另外两个阵营"，不包含自己和对方阵营

### 15.3 被抓后果

- 关禁闭3轮
- 偷窃失败（对方库存不减少）
- Agent仍停留在原地
